# 治理与授权验收

验收使用临时数据库、三个独立的普通投票成员和一个共享库管理员。另外使用一名提供过期报告的成员、一名未验证账号和一个其他库管理员检查边界。

| 场景 | 验收结果 |
| --- | --- |
| 举报与计票 | 同一人重复提交沿用原举报和计票时间。窗口外的报告、未验证账号和表达反馈均不计入暂停票。第三名有效成员触发暂停，审核记录包含全部有效票的编号。 |
| 暂停范围 | 错配只暂停相关问法，原问仍可复用。一条事实报告即让报告人绕开相应答案版本。管理员恢复后，下一轮单独计票。 |
| 发布与历史 | 主动重答单独写入会话。同一条重答只生成一份修订。发布使旧变体退出复用，聊天保留当时的答案。已处理或基于旧版的修订无法覆盖新版。 |
| 身份与权限 | 普通成员不能发布，其他库管理员不能管理此共享库，无效登录凭证不能读取记录。撤销成员资格后，精确和语义匹配均失去共享库可见性，重新初始化也不会恢复权限。 |
| 到期与复核 | 同一来源版本的六条并发请求只读取一次来源。内容一致时延长复核时间，变化时提交一条候选修订并等待审核。缺少来源时提示无法确认。 |
| 日期 | 上海跨午夜后切换到次日，洛杉矶同一时刻仍显示前一日。日期工具调用云端次数为零。 |

从项目根目录运行 `python backend/tests/governance_acceptance.py`。脚本使用本地模型模拟服务和临时来源目录，覆盖真实 API 路由、数据库和客户端权限检查。

## 配置

共享暂停默认使用 7 天和 3 个有效成员。服务端可通过 `QISHI_PAUSE_WINDOW_DAYS` 和 `QISHI_PAUSE_THRESHOLD` 调整。

到期复核读取维护者配置的本地 JSON 目录。将 `QISHI_SOURCE_CATALOG` 设为该文件的绝对路径。目录按来源键记录版本和答复正文，例如：

```json
{
  "mac-window-capture": {
    "version": "2026-11",
    "answer": "按 Shift + Command + 4，再按空格键并点击目标窗口。"
  }
}
```

在项目根目录运行下列命令将已有问答绑定到对应来源。在同一数据目录使用第二条命令撤销指定共享库成员资格。

```powershell
$env:PYTHONPATH = "backend"
python -m app.cli set-source --group grp_mac_shot --key mac-window-capture --version 2026-11 --review-days 7
python -m app.cli revoke-member --id "<用户 ID>" --library QS-2048
```

目录内容由维护者从实际来源更新。本阶段通过测试目录验收复核和审核流程，线上来源需要各自的数据接入。
