# CPU 与费用验收

2026-11-21 在 Windows 11 家庭版（Build 26200）完成。测试机使用 Intel Core Ultra 7 251HX（18 核、18 逻辑处理器），可用物理内存约 15.4 GiB。测试服务禁用了 GPU 和可选的向量模型、重排模型。本地文本匹配没有加载模型权重。浏览器完成一次问答后，离线后端进程的工作集约为 58 MiB。

关闭云端 API 后，网页能登录并显示未收录问法的库内答案。API 验证了 12 条库内回答，包括 2 条原问、2 条已收录改写和 8 条未收录改写。计算器也能离线回答。未知问题提示云端不可用。8 条语义命中的本地匹配接口往返耗时中位数为 31 ms，最高 34 ms。12 条库内回答的首字和完成耗时中位数分别为 42 ms 和 92 ms。

恢复云端后，`deepseek-v4.1-flash-1017` 成功回答了「什么是拓扑排序？」并生成 5 条等价问法。后台使用 1 次调用，消耗 640 个输入 Token 和 324 个输出 Token。本次没有产生重试或更新。对照测试也覆盖了失败重试进入用量统计的情形。

## 26 条固定样本对比

沿用上一步独立验收的 26 条样本和固定问答库。每题真实请求云端一次，另在离线环境实测 12 条库内命中。四种配置根据允许的命中路径组合这些实测数据，避免为同一问题重复计费。首字和完成时间取客户端收到第一段正文与终止事件的中位数。云端基线最高四路并发，回放的云端耗时未叠加未命中时的本地检索开销。

| 复用配置 | 核心答案通过 | 正确且零云端调用 | 回答调用 | 后台调用 | 首字中位数 | 完成中位数 | 每百次输入 Token | 每百次输出 Token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 全走云端 | 25/26 | 0/26 | 26 | 0 | 2.39 秒 | 4.44 秒 | 8,127 | 79,108 |
| 只复用原问 | 25/26 | 2/26 | 24 | 0 | 2.33 秒 | 4.02 秒 | 7,500 | 74,896 |
| 原问和已收录改写 | 25/26 | 4/26 | 22 | 1 | 2.26 秒 | 3.57 秒 | 9,365 | 71,842 |
| 再加入语义匹配 | 25/26 | 12/26 | 14 | 1 | 1.39 秒 | 2.04 秒 | 6,862 | 53,000 |

正确率按是否答对核心事实或给出符合对象和条件的可用操作人工评估。12 条库内答案均通过，误复用为 0。各组均有 1 条云端答案未通过。「Mac 怎么只截一个屏幕？」的首选步骤将窗口捕捉当成捕捉指定显示器的方法。苹果文档将该快捷键用于捕捉窗口或菜单，并提供框选区域的独立方式。附带建议按同一核心答案标准评估。 [苹果截图文档](https://support.apple.com/102646)

含改写的两组各计入一次实测后台改写，将其开销分摊到 26 条样本。完整复用在这组样本里将回答调用减少 46%，计入后台改写后的总调用减少 42%，输入和输出 Token 合计减少 31%。当前配置缺少该模型的实际输入和输出单价。每百次请求的金额按表中输入与输出 Token 分别乘以各自的百万 Token 单价，再除以一百万。

## 复跑

在项目根目录运行以下命令。离线验证需要已构建的 `frontend/dist`。

```powershell
python backend/tests/cpu_cost_benchmark.py --output "$env:TEMP/qishi-offline.json"
python backend/tests/cpu_cost_benchmark.py --cloud --output "$env:TEMP/qishi-cpu-cost.json"
```

`--cloud` 会读取环境变量或根目录 `.env`，请求 26 条对照问题以及 1 条恢复验证问题，后者会触发后台改写。若配置了 `CLOUD_INPUT_USD_PER_MTOK` 和 `CLOUD_OUTPUT_USD_PER_MTOK`，结果同时给出每百次请求的美元估算。两种模式都使用临时数据库。
