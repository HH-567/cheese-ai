# 接入说明：把它变成你自己项目里的登录

> 本包是**运行版**：只含跑起来需要的东西。文中提到的 `tools/`（图标描迹、音频编解码、
> 打包校验）与 `tests/`（回归断言）不在包里，要改图标或重切台词请回到开发工作区。

三条路，从轻到重。

---

## 路线 A：只换文案和账号（几分钟）

改 `assets/qishi.config.js` 这一个文件：

```js
brand:  { zh: '柒柿 AI', en: 'QISHI', accent: '#ff7500',
          line2: 'ACCESS CONTROL', tag: ['ACCESS','GATE'],
          welcomeBox: 'QISHI AI', welcomeLabel: 'Q I S H I  ·  A I', footer: 'POWERED BY QISHI' },
intro:  { enabled: true, sound: true, voice: true, allowSkip: true, skipWhenSignedIn: true },
demo:   { account: 'qishi', password: 'qishi2026', display: '柒柿', level: '3' },
app:    { kicker: 'ACCESS CONSOLE', showAudit: true }
```

`accent` 不只是个点缀：光标、步骤读数、终幕那句「WELCOME TO / 欢迎 XXX 访问」的高光、
以及色散副本的暖色那一路，全都读它（上游原版这块是青色，覆盖写在 `assets/qishi.css` 里）。

`demo` 那段**只在本地库第一次建起来时写入**。库已经存在的话，改它不会覆盖已有账号 ——
想重置就清掉浏览器里 `localStorage` 的 `qishi.auth.v1` / `qishi.device.v1`。

## 路线 A+：换 logo

标识必须是矢量（第 3 幕「一笔画成」用 `getTotalLength()` + `strokeDasharray` 描边，
位图进去动画就死了）。所以给了条从位图描迹的流水线：

```bash
# 1) 把你的 logo 存成 assets/icon/source-*.png（纯色底、单色墨迹最稳）
python tools/vectorize-icon.py          # 位图 → 路径，自带 IoU 校验（<0.99 直接拒绝输出）
node   tools/apply-icon.mjs             # 路径 → splash.js 的 BRAND_PATH + favicon.svg
node   tools/shot.mjs assets/icon/preview.html shots/icon-compare.png   # 拍张对照图看看
```

一次改到 5 个地方：第一幕黑幕、第 3 幕装配、终幕、登录卡/控制台顶栏、favicon。

细节：

- 描迹脚本会按 `fill-rule="evenodd"` 输出**一条 d、多个子路径**：外轮廓 + 所有孔洞
  （字腔、图形里的细缝）。所以你的 logo 里如果有镂空，不用单独处理。
- 路径归一化到 50×50 的 viewBox、四周留 1.6 单位；尺寸由 CSS 控制
  （`assets/qishi.css` 里那几个 `#dsh-startup-root .dsu-logo svg` 就是）。
- 极小尺寸（20–26px）下细节会糊，这是"实心块 + 细缝"这类图形的必然。要小尺寸清楚，
  得另出一枚简化版图标，那是重做图形，不是这条流水线能解决的。
- 不想用工具、只想手写一条简单路径也行：把 `assets/icon/qishi-icon.js` 里的
  `__ICON_D__` 换成你的 `d`，再跑 `apply-icon.mjs`。

## 路线 B：接到你自己的后端（推荐）

前端只认一份契约，服务端什么语言都行。

### 1. 服务端要提供

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/api/login` | `{ account, password }` | `200 { user }` / `401 { code, message, remaining?, waitMs? }` |
| POST | `/api/register` | `{ account, password, display }` | `200 { user }` / `409 { code, message }` |
| POST | `/api/logout` | — | `204` |
| GET | `/api/session` | — | `200 { user }` / `401` |

`user` 的形状（前端只读这几个字段）：

```json
{ "account": "qishi", "display": "柒柿", "serial": "3831",
  "level": "3", "createdAt": 1730000000000, "lastLoginAt": 1730000000000 }
```

`code` 建议沿用：`BAD_CREDENTIALS` / `LOCKED` / `EXISTS` / `WEAK` / `BAD_ACCOUNT`。
前端已经会把这些翻译成人话；`LOCKED` 带 `waitMs` 时登录框会自动开始倒计时。

### 2. 前端要改两处

```html
<!-- index.html：放在 qishi-auth.js 之后、qishi-gate.js 之前 -->
<script src="assets/auth/auth-http.example.js"></script>
```

```js
// qishi.config.js
auth: { adapter: 'http', maxFails: 5, minPassword: 8 }
```

`auth-http.example.js` 里的 `BASE` 和四个请求路径按你的服务端改。它默认
`credentials: 'same-origin'`，也就是**会话走 Cookie**。

### 3. 服务端实现要点（别踩的坑）

- **口令只存哈希**：`scrypt`（Node 内置）或 `argon2id` 优先，PBKDF2-SHA256 ≥ 60 万次也够用；
  每个用户独立随机盐；比较用定长比较。
- **会话用 HttpOnly + Secure + SameSite=Lax 的 Cookie**，前端拿不到 token，XSS 也偷不走。
- **CSRF**：Cookie 会话必须防 CSRF —— 校验 `Origin`/`Referer`，或双提交 token。
  `SameSite=Lax` 能挡住大部分跨站表单，但别只靠它。
- **失败锁定在服务端做**：前端倒计时只是体验，绕过前端太容易。
- **登录响应别区分「没这个人」和「口令错」**，都一样回 `BAD_CREDENTIALS`（防账号枚举）。
- **审计留服务端**：`history()` 现在返回 `[]`，要显示就再加一个 `GET /api/audit`。
- 口令最小长度别低于 8；别明文写进日志；别把 `password` 回显进错误信息。

### 4. 为什么值得换

本地适配器是「在前端校验口令」，等于把校验权交给对手。真实项目里：

| | 本地适配器 | 后端适配器 |
|---|---|---|
| 口令校验 | 在浏览器 | 在服务端 |
| 会话签发 | 前端签名（同机可伪造） | 服务端签发 HttpOnly Cookie |
| 抗改前端 | 不抗 | 抗 |
| 适合 | demo / 离线样机 / 交互样板 | 真实系统 |

## 路线 C：把片头单独拿去用（不要登录）

只想要那支动画当启动页/落地页：

```html
<link rel="stylesheet" href="vendor/dsh-boot-suite/lib/splash.css">
<div id="dsh-startup-root" class="dsu-root dsu-boot"></div>
<script>
  window.__QISHI_ASSET_BASE__ = './vendor/dsh-boot-suite/lib/assets'
  window.__DSH_STARTUP__ = { enabled: true, theme: 'light', identity: 'OPERATOR' }
</script>
<script defer src="vendor/dsh-boot-suite/lib/splash.js"></script>
```

不注入 `window.__QISHI_LOGIN__` 时，第 2 幕就是**原版行为**（只读身份卡 + 点一下继续）——
补丁是加法，不接登录桥就不改变任何东西。

## 改拦截点：登录不一定在第 2 幕

`assets/ui/qishi-gate.js` 是唯一知道「登录框长在第 2 幕」的地方。要挪到第 1 幕、或者加第 7 幕，
改 `splash.js` 里 `BUILTIN_STEPS`（或者给页面注入一个 `window.__DSH_STARTUP_TEMPLATE__`，
分幕本来就是数据：`steps[]` 每项支持 `zh/en/say/audio/log/badge/action/hold/progress`，
`action` 取 `grant | confirm | auto`，`confirm` 那一幕会走登录桥）。

`qishi-gate.js` 对外只有两个方法：

```js
window.__QISHI_LOGIN__ = {
  mount({ card, btn, hint, btnZh, btnEn }) { /* 把表单画进 card */ },
  wait({ resolve, step }) { /* 核验通过后调用 resolve()，动画才会往下走 */ },
  btnZh: '验证身份', btnEn: 'VERIFY IDENTITY', hint: '…'
}
```

## 常见问题

**双击打开听不到配音？**
`file://` 下浏览器不允许 `fetch` 本地文件（同源策略），所以声音走的是补丁 6 的 `<audio>` 兜底。
如果连这个都被静音，检查右上角音量、或把页面放到任意静态服务器上（`?nosound=1` 是主动静音）。

**刷新之后片头不放了？**
`intro.skipWhenSignedIn` 默认 `true`：已经登录就直接进控制台。想每次都看片头，
设成 `false`；或者点控制台右上角「重播开场」。

**忘了口令？**
本地库没有找回流程（演示项目）。清掉 `localStorage` 的 `qishi.auth.v1` 会重新播种演示账号。

**能用手机打开吗？**
样式有 860px 以下的单列断点，但片头的版式是按 16:9 桌面调的，窄屏上会挤。要真做移动端，
建议 `intro.enabled = false`（直接进登录卡）再单独调。

**改坏了怎么退回？**
`vendor/` 是原样搬运的，删掉重拷一份即可；`assets/` 全是新增文件，删了不影响 `vendor/` 单独跑。
